Event Loop Concept
1. Function1 runs on the Call Stack
2. setTimeout() is called → handed off to Web API (leaves the stack)
3. Call Stack continues running other code (non-blocking)
4. Timer expires → callback moved to Task Queue
5. Event Loop checks: "Is Call Stack empty?" 
6. If yes → pushes callback onto Call Stack
7. Callback executes

Call Stack  →  Promise Queue (Microtask)  →  Task Queue (Macrotask)
This is why a resolved Promise will always execute before a setTimeout even if the timeout is 0ms — the Event Loop always drains the Promise Queue completely before touching the Task Queue.

Your Fetch Example with Event Loop
1. Function1 calls fetch() → handed off to Web API
2. Call Stack moves on
3. Response arrives → callback goes to Promise Queue
4. Event Loop checks Promise Queue FIRST (higher priority)
5. Then checks Task Queue
6. Pushes resolved callback onto Call Stack
